# Player Model v3: Report

The rules were pre-registered in `docs/players_v3_preregistration.md` (commit `59b5a33`) before any v3
feature was computed. The full tables are in `docs/players_v3_results.md` and `data/backtests/players_v3.json`,
regenerated by `python -m engine players-v3`. The run happens in three stages, in the pre-registered order:
1. Tune on the training seasons.
2. Run the validation checks.
3. Only after every check passes, score the test seasons.

## What v3 adds to the score projection

v1 rates teams from their scoring history alone. v3 multiplies each team's expected touchdowns and field goals
by exp(β·x), where x is:

| Variable | Built from | Point-in-time rule |
|---|---|---|
| `qb_delta` | EPA per dropback of the starting QB minus that of the QBs behind the team's rating. Uses play-by-play since 2006; each play is weighted 0.5^(days/D) and shrunk by k dropbacks toward a replacement level | Plays from earlier games only |
| `ol`, `skill` | Own injured players (Out / Doubtful / Questionable) × their snap share over the previous 4 games × P(not playing \| status) | Latest report row filed before lock; snaps from earlier games |
| `opp_dl`, `opp_lb`, `opp_db` | The same, for the opponent's defense | Same |
| `rest_diff`, `short_week`, `off_bye` | nflverse rest days | Known from the schedule |
| `tz_shift` | Time zones between the team's home stadium and the game site; international = 5 | Known from the schedule |
| `division`, `dome` | Schedule | Known from the schedule |

## Disclosures (limits that remain)

1. **Recorded starters, 2013–2024.**
   - Training and Test A use the recorded starting QB. That is normally known at inactives, 90 minutes before
     kickoff and so before lock, but it is an after-the-fact field.
   - To measure any hindsight, the results include a sensitivity run using the weekly depth-chart QB1 instead.
   - Those depth charts carry no timestamp, so neither source is a verified pre-lock record for those seasons.
   - Only 2025 uses timestamped snapshots.
2. **2025 injury rows have no timestamp.** For 2013–2024, at least 99.7% of report rows in every season are dated before lock, and the
   rows filed after lock are dropped. The 2025 release carries no `date_modified`, so its rows are used as
   published: the final game-status report comes out before the game.
3. **Depth-chart lag.** The last 2025 depth-chart snapshot before lock sometimes lists the injured
   starter as QB1. Example: SF week 3, where Purdy is listed but Mac Jones started. This is the real information
   available at lock, so it is kept, and the mismatch rate is reported.
4. **Snap-share window.** The previous 4 team games can cross a season boundary. A player new to a team has
   share 0 with that team.
5. **Replacement prior.** It is estimated on QBs whose first dropback in the data is 2007 or later, so that it
   marks a real career start. A veteran returning after a gap from before 2006 would be misread as a debut.
6. **Time zones.** Standard zones are used (Arizona counted as Mountain). The Bills' Toronto games count as
   international (1 training game).
7. **Schedule data errors fixed.** nflverse lists home-stadium ids for several international games (2021 and
   2025). Domestic neutral sites (Detroit 2010/2014/2022, Glendale 2020) are therefore named explicitly, and
   every other neutral site is treated as international.
8. **Train-only constants.** The replacement prior and the play probabilities come from 2013–2021 and are
   applied to training games as well. That is standard for constants, but it means training-season features
   are not strictly point-in-time for those two constants. Test seasons are.
